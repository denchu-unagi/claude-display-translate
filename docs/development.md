# 開発者向けの説明

翻訳モデルのファイルの作り方、ログの形式、内部の動作の詳細など、README の利用者向けの説明に入れていない内容です。

## 翻訳モデルのファイルを作る

ほかのモデルを使うときは、`translators/` に新しい名前のファイルを置いて `translate(prompt, timeout, settings)` を定義し、`MODEL` にそのファイル名から `.py` を除いた名前（英小文字・数字・`-` だけ。先頭は英小文字か数字）を書きます。引数と戻り値は次のとおりです。

- `prompt` は hook の翻訳指示と原文（`<source>` と `</source>` の間）を含む文字列です。
- `timeout` は使ってよい残りの秒数です。hook がこのファイルを起動して読み込むまでにかかった時間は差し引き済みです。
- `settings` は `settings.py` の変数です。
- 訳文は `<translation>` と `</translation>` で囲んだ文字列で返します。

`timeout` 秒で終わらないときは `TimeoutError` を送出すると、ほかの時間切れと同じく翻訳を5分休みます。`MODEL` にパスは指定できません。`MODEL` が指すファイルの実体（シンボリックリンク経由を含む）が `translators/` の外にあるときは実行しません。`haiku` は組み込みの Haiku を使う名前なので、`translators/haiku.py` を置いても読みません。モデルのファイルが中で読み込むものは制限しません。同梱のファイルは、取り直すと上書きされます。

## ログの形式

`translate.log` には1件の結果を1行の `key=value` で記録します。空白や引用符を含む値は JSON 文字列で囲みます。

```text
time=2026-10-18T12:00:00+0900 result=no_japanese message=a1b2c3d4-msg_01Example elapsed_sec=2.0 reply_head="The build failed because `npm ci` could not resolve a peer dependency."
```

| key | 内容 |
|---|---|
| `time` | 記録した時刻 |
| `result` | 結果の分類。翻訳に成功したときは `translated`、それ以外は失敗または翻訳を見送った理由 |
| `message` | セッションIDの先頭8文字とメッセージID。会話ログの該当メッセージを探すときに使う |
| `elapsed_sec` | 翻訳コマンドにかかった秒数。翻訳コマンドを起動したときだけ記録する |
| その他 | 結果ごとの補足（`translated_chars` は訳文の文字数、`source_chars` は長文で見送った原文の文字数で、どちらも閉じたコードブロックを短いプレースホルダーに置き換えた状態で数える。`exit_code` は翻訳コマンドの終了コードなど） |

`translate.log` の置き場所と、本文の一部を記録する条件は、README の[状態とログ](../README.md#状態とログ)にあります。

## 翻訳の起動とプロセスの後始末

翻訳用の `claude -p` は hook、tool、MCP、セッション保存を無効にして起動するので、翻訳が再帰しません。設定ファイルは hook とは別のプロセスで実行し、翻訳が終わるか制限時間を過ぎたら、設定ファイルと同じプロセスグループに残ったプロセスをまとめて止めます。設定ファイルが別のセッションで起動したプロセスは止められません。

## Orca のチャット画面の判定

Agent SDK 経由で起動する Orca のチャット画面で翻訳するのは、Orca がチャット画面の `claude` に `ORCA_STRUCTURED_SESSION` を設定していて、人が画面を見ているためです。チャット内の Bash ツールから起動した `claude -p` もこの変数を引き継ぐため、`ps` でプロセスの祖先をたどり、祖先に `claude` がいれば翻訳しません。スクリプトが読む出力を訳文に変えないためです。祖先が `claude` かは、プロセス名が同じか、Claude Code が実行中のセッションとして記録しているかで判定します。そのため、名前の違う `claude`（別の方法で導入したものなど）が入れ子になり、外側の `claude` の記録も見つからない場合（入れ子を別の `CLAUDE_CONFIG_DIR` で起動したときなど）は見分けられず、翻訳します。`ps` が使えないなど判定できないときは、チャット画面でも翻訳しません。

## README の注意に書いた動作の理由

- セッションを再開すると、再開前に訳文で表示していたメッセージが英語の原文で表示されるのは、会話履歴（transcript）には訳文ではなく原文が保存されていて、再開時はこの hook を通さずに表示されるためです。
- 書き出しの英語を見て `[自動翻訳]` を表示した後、メッセージ全体はほぼ日本語だと分かったときに、日本語の行を原文のまま表示するのは、日本語の行を翻訳に送ると、言い換えられた文が原文の代わりに表示されるおそれがあるためです。
- `|` で始まる表の行を英語の行として数えず、表示済みの表が空行で終わる前は切り替えないのは、表の行は担当名やモデル名など訳さない語が多く、表の途中に `[自動翻訳]` を表示すると表の1行として表示されるためです。
- 日本語が大半のメッセージで訳す英語が残るかを数えるときも表の行を数えないのは、表の中の英語は担当名やモデル名などの訳さない語であることが多く、表だけを翻訳に送ると訳文に日本語が増えず、翻訳の失敗になるためです。
- 作業中に表示される Claude の思考（thinking）と、ツールの実行結果を翻訳しないのは、`MessageDisplay` hook に渡されるのがメッセージの本文だけで、思考とツールの実行結果は渡されないためです。
