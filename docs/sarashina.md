# Sarashina で翻訳する

[Sarashina](https://sarashina.ai/) は、ソフトバンク傘下の SB Intuitions が開発する国産の LLM です。2026年11月時点では無償ベータ版として提供されていて、API も無料で使えます。

README の[翻訳モデルを変える](../README.md#翻訳モデルを変える)で `MODEL = "sarashina"` にすると、Sarashina で翻訳します。選ぶ前に、次の[注意](#sarashina-を使うときの注意)を読んでください。

## Sarashina を使うときの注意

[Sarashinaサービス利用規約](https://sarashina.ai/terms)のうち、この hook での使い方に関わる点です。

- 第3条により、利用できるのは日本国内に住む個人か、日本国内に本店がある法人だけです。
- 第10条により、個人を特定できる情報や第三者の著作物などは入力できません。この hook は英語の返答を自動で送るので、返答に人名やメールアドレスなどが含まれていても、閉じたコードブロックの外にあればそのまま送ります。
- 第9条と第11条により、送った文章と出力は、無償・有償を問わずモデルの学習に使われることがあります。学習への利用を拒否できるのは有償プランだけです。
- 4800字以上で空行がある原文は2部分に分けます。各部分（空行が無く分けないときは原文全体）が、閉じたコードブロックを除き inline code と URL をプレースホルダーに置き換えた状態で5000文字を超えるときは、Sarashina API が受け付けないため、`[翻訳失敗: 原文を表示]` を付けて原文を表示します。

## 訳し方

`MODEL = "sarashina"` にすると、翻訳 API（`sarashina3-translate`）だけで訳します。速さと翻訳の失敗の少なさを優先して選んだ構成で、品質が上がったわけではありません。意味の取り違えは、`sarashina3-mini` で見直していた以前の構成より残りやすいです。

翻訳 API には指示を渡せず、inline code の中の識別子まで日本語に訳すことがあります。そのため inline code と URL はプレースホルダーに置き換えて送り、訳文で元に戻します。送る直前に `[[[CODEn]]]` を `XQZnQ` の形に変え、受け取った訳文で戻します。翻訳 API はプレースホルダーを括弧ごと落とすことがあり、試した62個のうち、`[[[CODEn]]]` の形は56個、`XQZnQ` の形は61個が訳文に残ったためです。原文に同じ形の文字列があるときは変えずに送ります。

訳文でプレースホルダーが1回ずつ残っていないとき、または段落・箇条書き・見出しの数が送った文字列と違うときは、プレースホルダーを `[[[CODEn]]]` の形に戻し、`style` に `plain` を足してもう1回だけ訳します。2つの形はプレースホルダーを落とす位置が違い、`plain` では翻訳 API が箇条書きの2項目を1つにまとめる崩れが起きなかったためです。2回目も条件を満たさなければ1回目を使います。それでもプレースホルダーが欠けた・重複したときは原文を表示します。

翻訳 API は5000文字を超える入力を受け付けないため、原文が4800字以上のときは、空行の位置のうち大きいほうの部分が最も小さくなる位置で1回だけ切って2部分にします。空行が無いときは分けません。各部分は同時に訳して順につなぎます。英字を含まない部分は送らずにそのまま残します。

既知の限界:

- `sarashina3-mini` による照合をやめたので、意味の取り違え（否定・完了・合否など）は以前より残りやすいです。
- 括弧の中が inline code だけの部分は、翻訳 API が括弧ごと落とすことがあり、そのときは原文を表示します。
- 訳し直した部分（分割した片方だけのこともあります）は常体になります。

## 比較

README の[翻訳モデルの比較](../README.md#翻訳モデルの比較)と同じ英文と採点で比べた結果です。`claude-haiku-5-5` や `gpt-6-luna` などの結果は、README のその表にあります。Sarashina のモデルの時間は、API を直接呼んだ時間です。ただし `sarashina` の行は、下の注記のとおり、別の採点と hook の経路で測った値です。

| モデル | CLI | effort | 翻訳の中央値 | 得点（5段階） | 重大な誤訳 | 必須事実の欠落 | 判定 |
|---|---|---|---|---|---|---|---|
| `sarashina3-mini` | Sarashina API | — | 1.34秒 | 4.44 | 0件 | 0件 | 合格 |
| `sarashina`（`sarashina3-translate` だけ） | Sarashina API | — | 1.59秒 | 3.42 | 6件 | 6〜9件 | 不合格 |
| `sarashina3-translate` | Sarashina API | — | 1.27秒 | 3.67 | 3件 | 0件 | 不合格 |
| `sarashina3.2-mini-thinking` | Sarashina API | low | 10.62秒 | 4.31 | 1件 | 0件 | 不合格 |

- `sarashina`（`sarashina3-translate` だけ）は、`MODEL = "sarashina"` の翻訳プログラムを hook と同じ経路で測りました。時間は子プロセスの起動を含みます。得点は、ほかの行とは別の採点（構成名を伏せた2回）で測った値で、同じ採点の `claude-haiku-5-5` は 4.89 でした。重大な誤訳は、進行中の作業を完了扱いにする訳（short）と、check の合格を「完了」とする訳（mixed）で、どちらも3回とも出ました。
- `sarashina3-mini` と `sarashina3.2-mini-thinking` は、hook の翻訳指示をそのまま渡し、temperature などを API の既定値のまま測った参考値です。`sarashina3.2-mini-thinking` は effort を low にしました。この2つは `MODEL` では選べません。

## Sarashina の API キー

1. [API コンソール](https://chat.sarashina.ai/dashboard/api-keys)でキーを発行します。
2. Claude Code の外の端末で次を実行し、表示されたプロンプトにキーを貼り付けます。入力は画面に表示されず、自分だけが読めるファイル `~/.config/sarashina/api-key` に保存されます。

   ```bash
   ( umask 077; mkdir -p ~/.config/sarashina; printf 'Sarashina API key: '; read -rs key; echo; printf '%s\n' "$key" > ~/.config/sarashina/api-key )
   ```

- キーを Claude Code に貼り付けたり、このファイルを Claude Code に読ませたりしないでください。Claude Code が読んだキーは Anthropic に送られます。さらに `haiku` や `luna` に切り替えているときに Claude の返答にキーが含まれると、この hook がその提供元へも送ります。
- キーを別のファイルに置くときは、`settings.py` に `SARASHINA_API_KEY_FILE = "<ファイルのパス>"` を書きます。
- 原文にキーの値が含まれるときは、Sarashina に送らずに `[翻訳失敗: 原文を表示]` を付けて原文を表示します。
