# Sarashina で翻訳する

[Sarashina](https://sarashina.ai/) は、ソフトバンク傘下の SB Intuitions が開発する国産の LLM です。2026年11月時点では無償ベータ版として提供されていて、API も無料で使えます。

README の[翻訳モデルを変える](../README.md#翻訳モデルを変える)で `MODEL = "sarashina"` にすると、Sarashina で翻訳します。選ぶ前に、次の[注意](#sarashina-を使うときの注意)を読んでください。

## Sarashina を使うときの注意

[Sarashinaサービス利用規約](https://sarashina.ai/terms)のうち、この hook での使い方に関わる点です。

- 第3条により、利用できるのは日本国内に住む個人か、日本国内に本店がある法人だけです。
- 第10条により、個人を特定できる情報や第三者の著作物などは入力できません。この hook は英語の返答を自動で送るので、返答に人名やメールアドレスなどが含まれていても、閉じたコードブロックの外にあればそのまま送ります。
- 第9条と第11条により、送った文章と出力は、無償・有償を問わずモデルの学習に使われることがあります。学習への利用を拒否できるのは有償プランだけです。
- 4800字以上で空行がある原文は2部分に分けます。各部分（空行が無く分けないときは原文全体）が、閉じたコードブロックを除き inline code と URL をプレースホルダーに置き換えた状態で5000文字を超えるときは、Sarashina API が受け付けないため、`[翻訳失敗: 原文を表示]` を付けて原文を表示します。

## 訳し方

`MODEL = "sarashina"` にすると、`sarashina3-translate` だけで訳します。速さと翻訳の失敗の少なさを優先して選んだ構成で、品質が上がったわけではありません。意味の取り違えは、`sarashina3-mini` で見直していた以前の構成より残りやすいです。

`sarashina3-translate` には指示を渡せず、inline code の中の識別子まで日本語に訳すことがあります。そのため inline code と URL はプレースホルダーに置き換えて送り、訳文で元に戻します。送る直前に `[[[CODEn]]]` を `XQZnQ` の形に変え、受け取った訳文で戻します。`sarashina3-translate` はプレースホルダーを括弧ごと落とすことがあり、試した62個のうち、`[[[CODEn]]]` の形は56個、`XQZnQ` の形は61個が訳文に残ったためです。原文に同じ形の文字列があるときは変えずに送ります。

訳文でプレースホルダーが1回ずつ残っていないとき、または段落・箇条書き・見出しの数が送った文字列と違うときは、プレースホルダーを `[[[CODEn]]]` の形に戻し、`style` に `plain` を足してもう1回だけ訳します。2つの形はプレースホルダーを落とす位置が違い、`plain` では `sarashina3-translate` が箇条書きの2項目を1つにまとめる崩れが起きなかったためです。2回目も条件を満たさなければ1回目を使います。それでもプレースホルダーが欠けた・重複したときは原文を表示します。

`sarashina3-translate` は5000文字を超える入力を受け付けないため、原文が4800字以上のときは、空行の位置のうち大きいほうの部分が最も小さくなる位置で1回だけ切って2部分にします。空行が無いときは分けません。各部分は同時に訳して順につなぎます。英字を含まない部分は送らずにそのまま残します。

既知の限界:

- `sarashina3-mini` による照合をやめたので、意味の取り違え（否定・完了・合否など）は以前より残りやすいです。
- 括弧の中が inline code だけの部分は、`sarashina3-translate` が括弧ごと落とすことがあり、そのときは原文を表示します。
- 訳し直した部分（分割した片方だけのこともあります）は常体になります。

## 比較

`MODEL = "sarashina"` の構成は、訳の品質ではなく、速さと翻訳の失敗の少なさで選んでいます。下の表のとおり、品質は `claude-haiku-5-5` にも `sarashina3-mini` にも及びません。

比べた Sarashina のモデルは次の3つです。

| モデル | `MODEL` で選べるか | Sarashina に送るもの | モデルごとに足した処理 |
|---|---|---|---|
| `sarashina3-translate` | 選べる（`MODEL = "sarashina"`） | 原文だけ（指示は渡せない） | inline code と URL の置き換え、崩れたときの訳し直し、長文の2分割 |
| `sarashina3-mini` | 選べない | hook の翻訳指示と原文（Haiku に渡すものと同じ） | なし |
| `sarashina3.2-mini-thinking`（effort low） | 選べない | hook の翻訳指示と原文（Haiku に渡すものと同じ） | なし |

### 共通の英文での比較

README の[翻訳モデルの比較](../README.md#翻訳モデルの比較)と同じ回に、同じ英文6種類を各3回、どのモデルも hook と同じ経路で訳し、同じ採点で比べた結果です。時間は子プロセスの起動を含みます。

| モデル | 翻訳の中央値 | 得点（5段階） | 重大な誤訳 | 必須事実の欠落 | 判定 |
|---|---|---|---|---|---|
| `claude-haiku-5-5`（hook の既定） | 2.68秒 | 4.83 | 0件 | 0件 | 合格 |
| `sarashina3-translate`（`MODEL = "sarashina"`） | 1.55秒 | 3.42 | 6件 | 3件 | 不合格 |
| `sarashina3-mini` | 1.68秒 | 4.22 | 0件 | 0件 | 合格 |
| `sarashina3.2-mini-thinking`（effort low） | 10.26秒 | 4.19 | 0件 | 0件 | 合格 |

- 合格の条件と得点の付け方は README と同じです。重大な誤訳と必須事実の欠落は、18件のうち該当する試行の数です。採点役の指摘を、原文と訳文で照合して数えました。
- `sarashina3-translate` の重大な誤訳は、進行中の作業を完了扱いにする訳（short）と、check の合格を「完了」とする訳（mixed）で、どちらも3回とも出ました。short の誤りは必須事実の欠落にも数えています。
- この6種類では、`sarashina3-translate` 用の訳し直しも分割も起きませんでした。訳し直し・分割と、送る直前のプレースホルダーの形の変換を除いて `sarashina3-translate` に送った場合も、得点 3.58、重大な誤訳6件、必須事実の欠落3件と近い結果でした。
- `sarashina3-mini` は、長文（long）の3回とも、hook の翻訳指示にある `[[[CODEn]]]` という文字列を訳文に書き足しました。意味は変わらないので重大な誤訳には数えていませんが、表示は崩れます。
- `sarashina3-mini` と `sarashina3.2-mini-thinking` は、temperature などの生成設定を調整せずに測りました。`sarashina3.2-mini-thinking` は、中央値が Haiku の約4倍で、長文は3回とも25〜33秒かかりました。

### 失敗例での比較

上の6種類では、`sarashina3-mini` のほうが得点が高く、重大な誤訳もありません。それでも `MODEL = "sarashina"` を `sarashina3-translate` で訳す構成にしているのは、実際の返答で翻訳の失敗が少ないためです。作者の手元で原文表示になった返答などを元にした34件を、hook と同じ経路で1回ずつ訳すと、翻訳に失敗して原文を表示した件数は次のとおりでした。

| モデル | 翻訳の失敗 |
|---|---|
| `claude-haiku-5-5` | 0件 |
| `sarashina3-translate`（`MODEL = "sarashina"`） | 1件 |
| `sarashina3-mini` | 6件 |

- 34件のうち5件は、日本語が大半で、英語が表の中の名前などだけの返答です。この5件はどのモデルでも hook が翻訳に送らず、`[日本語が大半のため原文を表示]` を付けて原文を表示したので、表の件数に含めていません。
- `sarashina3-translate` の1件は、上の既知の限界に書いた、括弧の中が inline code だけの部分を括弧ごと落とす例です。
- `sarashina3-mini` の6件は、どれも日本語を含まない訳文（英語のままなど）が返ったものです。`sarashina3-mini` では、この失敗を減らす工夫を試していません。`sarashina3-translate` 用の訳し直しと分割は、この34件の失敗を減らすために入れたものです。

## Sarashina の API キー

1. [API コンソール](https://chat.sarashina.ai/dashboard/api-keys)でキーを発行します。
2. Claude Code の外の端末で次を実行し、表示されたプロンプトにキーを貼り付けます。入力は画面に表示されず、自分だけが読めるファイル `~/.config/sarashina/api-key` に保存されます。

   ```bash
   ( umask 077; mkdir -p ~/.config/sarashina; printf 'Sarashina API key: '; read -rs key; echo; printf '%s\n' "$key" > ~/.config/sarashina/api-key )
   ```

- キーを Claude Code に貼り付けたり、このファイルを Claude Code に読ませたりしないでください。Claude Code が読んだキーは Anthropic に送られます。さらに `haiku` や `luna` に切り替えているときに Claude の返答にキーが含まれると、この hook がその提供元へも送ります。
- キーを別のファイルに置くときは、`settings.py` に `SARASHINA_API_KEY_FILE = "<ファイルのパス>"` を書きます。
- 原文にキーの値が含まれるときは、Sarashina に送らずに `[翻訳失敗: 原文を表示]` を付けて原文を表示します。
